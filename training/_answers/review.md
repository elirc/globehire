# SEALED: model review of GlobeHire `src/` (main @ 22eeb47)

Ranked by production severity. **VERIFIED** means it was reproduced with a throwaway test against the running API (WebApplicationFactory, "Testing" environment) on 2026-09-24; the probe was deleted afterwards. The other findings rest on static evidence.
`[AI-smell]` marks the typical old-AI-generated patterns: docs claiming more than the code does, stub endpoints dressed up as features, and fixes applied to one instance of a pattern but not its siblings.

## What's genuinely good (say so in a real review)

- The tenant-scoped repository ports (`IHireCaseRepository.FindAsync(ClientId, Guid)`) and composite keys: cross-tenant GUIDs return 404.
- The half-open `[from, to)` policy ranges with overlap detection (`CountryEmploymentPolicy.cs:69-70`, `CountryPolicySelector.cs:18-27`).
- `MoneyAllocator` largest-remainder allocation (`MoneyAllocator.cs:14-24`).
- Honest docs: ADR-0002 and `/health/ready` disclose `durable = false`.
- Architecture tests enforce dependency direction (`tests/GlobeHire.Architecture.Tests/DependencyDirectionTests.cs`).

## Grading notes

- Finding 4 is the one that separates readers from reviewers. You only find it by comparing the hire-case write path with the offer write path, *not* by trusting FLAW-HARVEST.
- Findings 3 and 5 are the ones that would actually cost money in a pilot. Missing both means you reviewed shapes, not retries.
- Credit finding 1 only if the learner said *where* the claim-to-route check has to go (before the handler, in one place), not just "add auth".
